### Approach + Steps

**New module** `src/analyze_stock_kpi/data_sources/sec/xbrl.py` (mirrors
`sec/submissions.py`'s header/`require_https`/timeout shape — read that file
first, it's the template):

```python
_REVENUE_CONCEPTS = (
    "Revenues",
    "SalesRevenueNet",
    "RevenueFromContractWithCustomerExcludingAssessedTax",
)

def fetch_xbrl_concept(cik: str, concept: str, unit: str = "USD") -> float | None:
    """GET companyconcept for `concept`; None on 404 (not reported) or empty units."""
    url = settings.edgar_xbrl_url_template.format(cik=cik.zfill(10), concept=concept)
    request = urllib.request.Request(url, headers={  # same 3 headers as submissions.py
        "User-Agent": settings.sec_user_agent,
        "Accept": settings.http_accept,
        "Referer": settings.sec_referer,
    })
    require_https(request.full_url)
    try:
        with urllib.request.urlopen(request, timeout=settings.request_timeout_sec) as response:
            payload = json.loads(response.read())
    except urllib.error.HTTPError as exc:
        if exc.code == 404:
            return None
        raise
    return _extract_latest_value(payload, unit)

def _extract_latest_value(payload: dict, unit: str) -> float | None:
    facts = payload.get("units", {}).get(unit, [])
    if not facts:
        return None
    latest = max(facts, key=lambda f: (f["end"], f.get("filed", "")))
    return float(latest["val"])

def fetch_revenue(cik: str) -> float | None:
    for concept in _REVENUE_CONCEPTS:
        value = fetch_xbrl_concept(cik, concept)
        if value is not None:
            return value
    return None

def fetch_net_income(cik: str) -> float | None:
    return fetch_xbrl_concept(cik, "NetIncomeLoss")

def fetch_eps(cik: str) -> float | None:
    return fetch_xbrl_concept(cik, "EarningsPerShareBasic", unit="USD/shares")

def _delta_pct(yf_value: float | None, sec_value: float | None) -> float | None:
    """(yf - sec) / sec; None if either operand missing or sec_value == 0."""
    if yf_value is None or sec_value is None or sec_value == 0:
        return None
    return (yf_value - sec_value) / sec_value

def enrich_snapshot_xbrl(snap: FundamentalsSnapshot) -> dict:
    cik = resolve_cik(snap.symbol)
    if not cik:
        return {}
    try:
        sec_revenue = fetch_revenue(cik)
        sec_net_income = fetch_net_income(cik)
        sec_eps = fetch_eps(cik)
    except urllib.error.URLError as exc:
        logger.warning("SEC XBRL fetch failed for %s (CIK %s): %s", snap.symbol, cik, exc)
        return {}
    return {
        "sec_revenue_delta_pct": _delta_pct(snap.total_revenue, sec_revenue),
        "sec_net_income_delta_pct": _delta_pct(snap.net_income_to_common, sec_net_income),
        "sec_eps_delta_pct": _delta_pct(snap.trailing_eps, sec_eps),
    }
```

## 3. #340 — adopt `qte77/.github` tag-release + publish-release only

### Context

Issue #340 proposed adopting three `qte77/.github` reusable release workflows
(bump, tag, publish). While scoping this, found the estate's own authoritative
tracker, `qte77/qte77#126` (open), already settled the design: **no reusable
bump workflow** — "the human merge is what makes tagging fire, so none are
needed (YAGNI)." #340 predates that decision. **Decided: adopt tag+publish only;
`bump-my-version.yaml` stays local, unchanged.**

Verified live: `qte77/.github`'s `tag-release.yml` and `publish-release.yml` are
behaviorally identical to this repo's current inline versions (same
idempotency/never-delete guardrails, same `awk` changelog extraction) — this is a
low-risk, near-mechanical swap.

### Approach + Steps

**`.github/workflows/tag-release.yaml`** — replace entirely with:

```yaml
name: Tag Release
on:
  push:
    branches: [main]
    paths: [pyproject.toml]
jobs:
  tag:
    permissions:
      contents: write
    # No release tag exists yet on qte77/.github; pinned to main HEAD
    # (resolved 2026-09-21) — re-pin once a real tag exists.
    uses: qte77/.github/.github/workflows/tag-release.yml@4801217a20922cd54187fc7e4c98c7ea78c0ec9a
```

No `with:` needed — this repo's `pyproject.toml` version line matches the
reusable's defaults exactly (`version_file: pyproject.toml`, `tag_prefix: v`,
`version_regex: ^version = "(.*)"`).

**`.github/workflows/publish-release.yaml`** — replace entirely with:

```yaml
name: Publish Release
on:
  workflow_dispatch:
    inputs:
      tag:
        description: "Tag to release (defaults to the latest v* tag)"
        required: false
        type: string
jobs:
  publish:
    permissions:
      contents: write
    uses: qte77/.github/.github/workflows/publish-release.yml@4801217a20922cd54187fc7e4c98c7ea78c0ec9a
    with:
      tag: ${{ inputs.tag }}
```

No override needed for `changelog_path`/`tag_prefix` — defaults match.

**SHA pin, resolved:** this repo has `sha_pinning_required: true` (verified via
the Actions permissions API); GitHub's docs confirm this governs "actions and
reusable workflows" together, so `@main` (issue #340's own sketch) isn't
acceptable — both `uses:` above are pinned to `qte77/.github`'s current `main`
HEAD, since no release tag exists yet.

**Allow-list — verify empirically, not a hard blocker:** this repo's Actions
allow-list (`patterns_allowed`) doesn't list `qte77/.github`, yet two other
qte77-owned actions absent from that same list (`qte77/gha-sbom-action`,
`qte77/gha-llms-txt-action`) run successfully today — enforcement clearly allows
more than the settings API surfaces. Land `tag-release.yaml` first, watch its
first live run. If it fails with an "actions not allowed" error: add
`qte77/.github` via Settings → Actions → General → Allow list (or
`gh api repos/qte77/analyze-stock-kpi/actions/permissions/selected-actions -X PUT`
with `qte77/.github` appended to `patterns_allowed`) — then land
`publish-release.yaml`.

**`CONTRIBUTING.md`'s "Release flow" section** — rewrite (found stale
independent of this change: it describes a fully manual
`uv run bump-my-version bump` + `git push --tags` flow that already doesn't
match reality — `bump-my-version.yaml` is already CI-automated today,
predating this PR):

```markdown
## Release flow

Semi-automated: bump is a manual dispatch, tag + publish are automatic /
on-demand `workflow_call` callers to `qte77/.github`'s reusable workflows.

1. **Bump** — trigger `bump-my-version.yaml` via `workflow_dispatch` (choose
   `major`/`minor`/`patch`). It bumps `pyproject.toml` + the README version
   badge, syncs `uv.lock`, collects `changelog.d/` fragments via `scriv`, and
   opens a release PR — review and merge it like any other PR.
2. **Tag** — merging that PR to `main` (a `pyproject.toml` version change)
   triggers `tag-release.yaml`, which calls `qte77/.github`'s reusable
   `tag-release.yml` to create the annotated `v{X.Y.Z}` tag automatically.
   Idempotent — aborts rather than overwrites if the tag already exists.
3. **Publish (optional)** — trigger `publish-release.yaml` via
   `workflow_dispatch` to call the reusable `publish-release.yml`, which
   creates a GitHub Release from the tag using the `CHANGELOG.md`
   `## [X.Y.Z]` block. Also idempotent — aborts if a Release already exists.

Neither tag nor publish ever deletes a tag/Release on failure — release
immutability means a deleted tag name is unusable forever (`qte77/.github#23`).
`bump-my-version.yaml` stays a local, repo-owned workflow rather than a
`qte77/.github` reusable call by design — see `qte77/qte77#126` ("no
reusable-bump"; human-merge-triggers-tag is the intended flow estate-wide).
```
