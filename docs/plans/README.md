# Implementation Plans

Working implementation plans for tracked issues — the **how**, sitting between the
issue (the *what* / *why*) and the code.

- One file per substantial issue: `NNNN-slug.md` (`NNNN` = the issue number).
- Structure: **Context · Approach · Steps · Open questions · References**.
- A plan is a living draft. It may **graduate to an ADR**
  ([`../decisions/`](../decisions/)) once a load-bearing decision in it is locked,
  or be deleted once the issue ships.

Thin issues (a one-file tweak, a process tracker) stay issue-only — no plan file.
